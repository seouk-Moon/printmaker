# 검증 기록

## 로컬에서 확인한 것

- `npm test`: 데이터 유효성, 중복 ID, 이미지 URL 안전성, 문제 수, Moonwords 정답 번호 변환 등 8개 테스트 통과.
- `npm run build:pages`: TypeScript 검사와 GitHub Pages용 빌드 성공.
- 서버 코드는 esbuild로 TypeScript 구문 검사. 실제 Deno·Supabase 실행을 대신하지 않습니다.
- Chromium에서 개발 화면과 `/printmaker/` 하위 경로의 실제 프로덕션 빌드를 확인. 브라우저 오류 없음.
- 프로덕션 화면의 문제만/답지만/합본 × Word/PDF 여섯 버튼을 눌러 실제 파일 다운로드 확인.
- 3문제 표본: 문제 2페이지, 답지 2페이지, 합본 4페이지. 합본 답지는 새 페이지에서 시작, 홀수 마지막 오른쪽 칸은 빈칸.
- 한글·영문·그림 포함 PDF를 렌더링해 확인. 나눔고딕 전체 글꼴을 포함해 부분 글자 누락을 해결.
- Word 3종을 LibreOffice로 PDF/이미지로 렌더링해 제목·중앙선·그림·답지·쪽 나눔 확인.
- 긴 문제 85문장 표본을 4페이지로 출력해 번호 유지와 ‘계속’ 표시, 잘림 없는 이어쓰기를 확인.
- 제공된 원본 양식 PDF를 앱에 올려 텍스트 읽기와 직접 문제 추가 확인.
- 390px 모바일 화면에서 가로 넘침 없음.
- Moonwords 전체 프로젝트의 `npm run build:pages` 성공. 기존 기능 코드는 변경하지 않고 하단에 Printmaker 링크만 추가.

## 배포 후 확인이 필요한 것

실제 Supabase 프로젝트나 Gemini 키로 요청하지 않았으며 GitHub/Supabase에 대신 배포하지 않았습니다. SQL 적용, RLS 계정 격리, Gemini 추출·변형·토의, 계정별 저장, 실제 도메인 간 화면 이동은 배포 후 확인해야 합니다.

1. 기존 Moonwords 프로젝트에서 README의 새 SQL과 `printmaker-ai`만 적용합니다.
2. 본인 계정으로 로그인해 학습지 저장·불러오기·삭제를 확인합니다. 테스트용 학습지만 삭제하세요.
3. 별도 테스트 계정에서는 다른 사용자의 학습지가 보이지 않는지 확인합니다.
4. 짧은 문제 PDF 한 페이지로 추출, 답안 연결, 변형 1문제, 후속 토의를 확인합니다.
5. ‘내 Moonwords 본문 가져오기’와 선택 문제 보내기를 확인합니다. 기존 본문은 그대로 있어야 합니다.
6. 출력 전 원본과 문제/그림/정답을 검토합니다. Word는 사용자의 글꼴·버전에 따라 재배치될 수 있습니다.

번들 크기 및 docx의 `buffer` 외부화 경고는 빌드 실패가 아니며, 프로덕션 브라우저에서 DOCX 다운로드를 확인했습니다.
