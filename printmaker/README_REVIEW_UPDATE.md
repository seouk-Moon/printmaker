# Printmaker 최종본 원본 연결·그림 수정 업데이트

## 포함 내용
- ‘최종본 확인 · 그림 수정’으로 실제 출력 PDF와 같은 미리보기를 표시합니다. 문제 영역을 누르면 해당 문제의 원본 페이지로 이동하고, 그림을 누르면 그 그림의 교체 모드로 이동합니다.
- 원본에서 손가락/마우스로 영역을 드래그한 다음 ‘선택 영역으로 이 그림 교체’를 누르면 선택한 그림만 바뀝니다. 글, 정답, 해설, 다른 그림과 문제는 유지하고 검토 완료 표시는 해제합니다. 빠진 그림도 새로 추가할 수 있습니다. 숫자 영역 조절도 지원합니다.
- 새 그림으로 PDF 미리보기를 다시 만들며 기존 문제/답지/통합 PDF·Word 다운로드 및 JSON 백업·계정 저장 기능은 유지합니다.
- 모바일: 전체 화면의 ‘최종 미리보기 / 원본 · 그림 편집’ 탭과 큰 버튼. 넓은 화면: 최종본과 원본을 나란히 표시합니다. 키보드 포커스·Esc·브라우저 뒤로가기 닫기도 지원합니다.
- 문제 원본 뒤에 답지를 올려도 앞서 읽은 원본을 유지합니다. 한 편집 세션 최대 60페이지입니다. 파일 내용의 해시와 페이지 번호로 출처를 구분하므로 이름이 같은 다른 파일로 잘못 이동하지 않습니다.
- 원본 전체는 현재 브라우저 편집 세션에만 보관합니다. 저장/백업에는 문제·잘라낸 그림·출처 식별자와 좌표만 포함됩니다. 다시 접속한 후에는 동일한 원본 파일을 다시 불러오세요. 예전 백업은 파일 이름·페이지로 고유하게 찾거나 페이지를 직접 선택할 수 있습니다.
- AI 추출에 문제 전체의 위치 좌표를 요청하도록 개선했습니다. AI 좌표는 부정확할 수 있으므로 원본을 확인한 뒤 영역을 조정하세요. 기존 데이터는 원본 페이지를 열고 수동으로 영역을 지정할 수 있습니다.

## 적용 방법
1. ZIP을 풀고 GitHub Desktop에서 Printmaker 저장소의 ‘Show in Explorer’로 저장소 루트를 엽니다.
2. 이 저장소는 루트 아래 printmaker 폴더 안에 package.json과 src가 있는 구조입니다. ZIP 안의 printmaker 폴더를 저장소 루트에 합쳐 넣어 같은 파일만 덮어씁니다. 폴더 전체를 삭제하지 마세요. 적용 후 경로는 printmaker/src/App.tsx입니다.
3. GitHub Desktop에서 변경 파일을 확인한 뒤 Commit → Push 합니다. GitHub Actions 배포를 기다리고 사이트를 새로고침합니다.
4. Supabase Dashboard → Edge Functions → printmaker-ai에서 ZIP에 포함된 printmaker/supabase/functions/printmaker-ai/index.ts의 전체 코드로 교체 후 재배포합니다. CLI를 쓰면 앱 폴더(설정 파일이 있는 printmaker)에서 `supabase functions deploy printmaker-ai`를 실행합니다. 기존 Gemini 키는 유지합니다. 추가 SQL은 없습니다.
5. 기존 함수 상태에서도 수동 원본 선택·그림 교체는 가능하지만, 새 문제 전체의 원본 위치 표시에는 수정된 함수 재배포가 필요합니다.

## 사용 순서
원본 업로드 → 문제 추출/편집 → 제목 입력 → 다운로드 탭의 ‘최종본 확인 · 그림 수정’ → 최종본 문제/그림 선택 → 원본에서 영역 선택 → 그림 교체/추가 → 최종본 확인 → 다운로드/백업/클라우드 저장.

검증: 프로덕션 TypeScript·Vite 빌드, 기존 모델 및 출처/그림 교체 12개 테스트 통과. 실제 브라우저에서 PDF 영역 클릭→원본 연결→드래그 교체→새 PDF 반영, 다른 내용 유지, 모바일 탭·데스크톱 두 화면·뒤로가기·JSON 백업 확인. 운영 Supabase 함수나 유료 AI를 호출하지 않았고, GitHub Push와 운영 배포는 하지 않았습니다.
